# Production contract

Choose only decisions that support this site's visitor action. A shopping product page may need an accurate product-detail insert with no overlay, rather than a lifestyle hero. A rental listing needs faithful property photography, not an invented villa. A software page may use a verified screen recording; if choosing an abstract workflow, label it as an illustration and do not fabricate actual UI, metrics or features.

## Request fit

Keep the user's explicit subject, motion, end pose, duration, aspect, fidelity and playback requirements in the continuity record. Fill unspecified choices with the defaults; an easier shot is not a completed version of a different requested shot. If requirements are compatible and supported, proceed without an extra creative questionnaire.

When a conflict changes the shot, state it briefly and ask only the decision needed to resolve it. Keep the affected END/video pending while doing any independent source work. For example, a front-facing subject completing360 degrees returns to the front; a rear END is a half-turn. Ask which end pose/turn the user means rather than silently delivering a small front push. A label saying an alternative is different does not authorize substituting its complete handoff. Offer a brief alternative if useful; expand it after the user chooses it or has already delegated fallback selection.

For requested rotations or reveals, check the net end angle and turn rate (degrees divided by seconds), then inspect verified views of every side that will become visible. Front imagery alone does not establish a real product's back, interior or fine marks. Preserve the requested shot as pending when those references are essential; do not invent the missing view or change to abstract art. A START-only tool can suggest a final pose but cannot enforce it, and two endpoints alone do not verify an entire turn's intermediate geometry.

For a requested loop, define the full cycle separately from the endpoint poses. Different endpoint angles cannot directly join seamlessly. A return movement can close a cycle only if compatible with the requested timing and action; describe its duration and role explicitly. Reverse playback is unsuitable for some directional actions, such as flowing water. Do not silently rename END as a midpoint or call matching stills a verified loop: rendered join position, velocity, exposure and intermediate motion need inspection.

## Endpoint continuity

Keep a concise continuity record before calling a generator: source image URL or file, what it actually depicts, START file/asset ID, which details must match, the one allowed change, and the intended display/crop. Use the exact accepted START on END calls. A matching brand palette or similar silhouette is insufficient for a literal product/property. If the homepage image cannot be mapped to a named listing, keep it at collection level or verify the mapping; do not transfer another page's amenities onto it.

List subject count, recognizable anchors, horizon/vanishing points, fixed light and materials. Derive one primary action from the observed product/service, its real use, the page's purpose and visual language. Record the source evidence, proposed editorial staging, moving element, START state, intermediate action, END state and camera's supporting role. Explain why it fits this offering. Do not turn these fields into a universal garment/rotation/hand-interaction template. A product-specific action can be illustrated without claiming it is recorded real footage, but may not invent a product feature, production process or material capability. Missing geometry or behavior essential to the chosen action remains a source gap.

A still source is not automatically a blocker or a reason to demand the user's own motion recording. For an illustrative website-film concept, ordinary physically plausible use or movement of the observed object may be proposed as editorial staging, while preserving its visible identity and avoiding precise fit, drape, elasticity, durability or performance claims. The proposed action does not have to be pre-recorded on the site. Require additional evidence only for an actually hidden feature/view or specific behavior essential to the shot, or when the brief demands an accurate physical demonstration. Choose a feasible action within available evidence before declaring the whole job blocked; do not turn the URL-only workflow into a mandatory product-video upload.

For an ordinary motion request, the scene must contain meaningful action beyond a global camera transform. Reject static catalog-to-detail zoom pairs of any scale as the default motion solution. Ask whether the scene states still show an action if their camera framing were aligned. Different crops, motion blur, a wind adjective or a more dramatic light are not evidence of that action. Preserve explicit camera-only, micro-motion and complete-cycle requests instead of forcing a different brief. For a cycle, record intermediate phases even when START and END return to the same pose; only rendered frames establish the actual action and join. Keep the plan feasible within its duration and inspect every source surface the action exposes.

When a camera scale is explicitly requested or supports a real action, apparent sizes scale coherently rather than independently deforming. This camera instruction does not replace the primary action. Keep fixed construction and identity distinct from permitted pose/articulation or physically plausible source-supported cloth motion; a blanket command to freeze all positions, folds and silhouettes would cancel the action.

Prefer the smallest necessary edit to existing faithful imagery over an expansive restaging that invents surroundings. Label each attached image's role (source identity, edit target, or accepted START), not just its filename. For a repair, say which defect changes and what stays fixed. Do not compensate for a failed literal product rendering by selecting a different abstract concept. If exact identity is important and the available tool keeps redrawing it, report that this output is not suitable for that use rather than promising pixel preservation through prompting.

Compose the key subject inside the central crop shared by the intended desktop and mobile layouts, with reasonable margins. For a full-height 9:16 crop of a 16:9 image, only about the middle 32% of the width remains; do not casually promise that widely spaced objects survive it. Keep text as live HTML, not generated raster lettering. Name the exact copy-safe region and whether it survives the mobile crop. If it does not, use copy above/below the media on mobile. A quiet dark background is not proof of sufficient contrast: check in the consuming page.

## Copyable prompts

Start prompt: state intended page location and aspect; describe the concrete opening action state, materials, lighting, lens, framing, negative space, source-image roles and explicit fidelity constraints. Compose for the planned action, not automatically as a floating catalog product. Avoid promotional slogans and unsupported facts. Include no text/logo if reliable raster lettering is not essential; an existing logo can be added later as a web layer.

End prompt: explicitly say “Use the generated START image as the primary image reference.” Repeat the concrete scene and fixed anchors so the prompt remains usable on its own. Describe the actual resulting action state and which poses/parts change, while preserving identity, construction and illumination. A bigger crop of an unchanged subject does not satisfy ordinary action. Do not restage the scene or introduce unrelated objects merely to create contrast.

Video prompt: identify START and END inputs; repeat the scene and product-specific primary action; give its intermediate phases and timing, and the camera's separate supporting role. Describe moving parts, contact/occlusion if applicable, and which identity features remain fixed. Match the action to the actual endpoint states rather than adding action verbs to two static crops. No dissolve between two photographs as a substitute for coherent motion. No sound, hard cuts or loop promise unless explicitly justified. If a target generator cannot support both endpoints, write a self-contained single-image video prompt that uses START only and describes the desired end state explicitly. Do not tell the user to paste a two-image prompt that still refers to an unavailable “supplied END”. Explain that the described end state is a guide, not an enforced last frame. If endpoint support is unknown, keep recommendations conditional and do not invent a provider's settings.

When actual generated dimensions differ from the requested ratio, report the actual ratio and choose an appropriate fit/export treatment. Never stretch or promise a lossless portrait crop. Copy-space measurements refer to the observed result, not the prompt's requested percentages. In prompt-only mode crop and continuity claims remain design intentions, not checked image facts.

## Media delivery advice

Suggested duration and frame rate are production recommendations, not an invented provider API. A 5-second, 24–30fps source is often adequate; site purpose decides. Choose a master with enough resolution for the placement and a smaller mobile derivative after actual export inspection. Use a lightweight poster and compressed web delivery. Do not set a universal byte target, autoplay policy or hardware-performance promise. Scroll films must be tested on actual visual output in both directions; reduced-motion can remain a still. Default distinct endpoints should play once or be scroll-controlled, not looped with a visible jump.
